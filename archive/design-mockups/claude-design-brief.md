# Claude Design 브랜딩 브리프 — Baseball Lab S&C

> `claude.ai/design`에 그대로 붙여넣어 사용. 가능하면 시작 시 현재 사이트 URL이나 `site/` 폴더를 함께 연결해 "웹 캡처" 또는 "codebase 연동" 기능으로 기존 비주얼을 먼저 인식시킨 뒤 이 브리프를 입력하면 결과 품질이 더 좋다.

## 프롬프트 본문 (복사 시작 ↓)

당신은 Baseball Lab S&C 웹사이트 전체의 브랜드 리뉴얼을 맡은 디자이너입니다. 아래 정보를 토대로 시각 시안 3가지 방향을 제안하세요. 이 사이트는 **두 가지 페이지 컨텍스트**가 있으며 두 컨텍스트가 **하나의 통일된 디자인 시스템**에서 일관되게 보여야 합니다. 모든 카피는 한국어입니다.

### 컨텍스트 ① 메인 앱 (index.html, 인터랙티브)
사용자가 데이터를 입력·확인·관리하는 도구 화면. 정보 밀도가 높고 폼·차트·모달이 많음.

### 컨텍스트 ② 문서/가이드 페이지 7개 (장문 텍스트, 단일 컬럼)
약관·소개·가이드 같은 정적 문서. 본문 가독성과 신뢰감이 핵심.

각 방향마다 두 컨텍스트의 핵심 화면을 모두 보여주세요:
- 메인 앱: (1) 히어로 (2) 선수 등록 폼 카드 (3) 선수 목록 카드 (4) 정밀 평가 결과 + ACWR 차트 (5) 7일 스케줄 (6) 팀 대시보드 (7) 컨디션/워크로드 모달 (8) 모바일 뷰
- 문서/가이드: (9) 문서 페이지 마스터 레이아웃 1종 (헤더·본문·각주·뒤로가기 링크 포함) — 7개 페이지가 같은 마스터로 렌더링되는 것을 보여주는 1~2개 샘플 (가이드 페이지 1개 + 약관 페이지 1개)

### 1. 제품 한 줄 정의
Baseball Lab S&C는 한국 아마추어 야구 선수(투수·타자)와 그들을 지도하는 코치·보호자를 위한 **훈련·회복·워크로드 관리 웹 도구**입니다. 정밀평가 8종, 7일 맞춤 스케줄, ACWR 기반 부하 관리, 일일 웰니스/회복 점수 기록을 한곳에서 제공합니다.

### 2. 핵심 사용자
- **유소년·학생 선수** (U-12 / U-15 / U-18): 자기 기록을 직접 입력하기도 하고, 보호자·코치가 대신 입력.
- **사회인 야구인 (성인 아마추어)**: 본인이 직접 사용.
- **취미·건강 목적 사용자**: 부상 회피와 컨디션 관리가 주 관심사.
- **코치·지도자**: 팀 대시보드로 여러 선수 모니터링.
- **보호자**: 자녀 선수의 회복/부하 상태 확인.

모두 한국어 사용자. 모바일에서 운동 직후 빠르게 입력하는 시나리오가 매우 많음.

### 3. 브랜드 톤
- **신뢰할 수 있고 정밀하게 측정한다는 인상.** 운동과학 기반 도구.
- **친근하고 접근 가능.** 의료기기처럼 차갑거나 위협적이지 않다.
- **야구라는 종목에 대한 존중.** 단, 클럽 굿즈·복고 야구 그래픽은 피한다 (가벼워 보임).
- **안전 보수적.** 의료적 단정/예측을 하지 않는 도구.

피해야 할 정체성: 게이밍/이스포츠 톤, 헬스장 보충제 톤, 의료기기 톤, 빈티지 유니폼 톤.

### 4. 표현 제약 (UI 카피와 마케팅 카피 모두에 적용)
다음 단어/뉘앙스는 **절대 사용 금지**: 치료, 처방, 진단, 부상 예방 보장, 성과 향상 보장, 최적, 자동 위험 판정, 부상 예측.

대체로 다음 같은 안전한 표현만 사용: 참고, 확인, 조정 고려, 도움이 될 수 있음, 전문가 상담 권장, 기록, 추적, 관리.

이유: 한국 의료법·광고법 리스크 회피.

### 5. 정보 구조 (보존해야 함)
현재 앱의 주요 화면과 핵심 요소들. 이 구조와 명칭은 유지하되 시각 디자인은 자유롭게.

#### 5-A. 메인 앱 화면 (`site/index.html`)
- **히어로**: "투수·타자 모두를 위한 야구 훈련·회복·워크로드 관리" + 8종목 정밀평가 / 7일 맞춤 스케줄 / ACWR 부하 관리 3가지 지표 강조. 헤더에는 "팀 대시보드", "처음 사용 가이드(3분 빠른 시작)" 버튼.
- **신규 선수 등록 카드**: 이름, 투수/타자 토글, 선수 유형(유소년·사회인·취미), 사용 관점(본인·코치·보호자), 훈련 방향(근력·체력·회복·가동성·경기준비·취미), 나이, 구력, 키, 체중, 최고/평균 구속, RPM, 다음 등판일.
- **초기 컨디션 설정 (Initial Condition)**: 통증 부위 체크 + 통증별 회복 점수 1~10 picker.
- **관리 중인 선수 목록**: 이름, 투타, 나이대, 보직/포지션, 현재 ACWR/워크로드 상태 시그널.
- **신체 정밀 평가 (8종목)**: 어깨/고관절 가동성, 코어, 균형, 점프, 스프린트 등 8개 항목 결과 시각화.
- **선수 결과 페이지**: 평가 결과 카드, ACWR 그래프 카드 2종(주간·일간), 7일 스케줄 카드.
- **7일 맞춤 스케줄**: 일별 운동 리스트, 운동 대체 기능, 휴식일 표기.
- **팀 대시보드 (코치용)**: 오늘 액션 큐(집중 관리 대상), 선수별 상태 요약.
- **모달 7종**:
  - 오늘의 컨디션 (Live Wellness) — 통증 부위·회복 점수·수면·피로도
  - 퍼포먼스 재측정 — 8종목 재측정
  - 운동 상세 (운동 이름/설명/대체 정보)
  - 운동 대체하기
  - Baseball Lab S&C 사용 가이드
  - 사후 워크로드 입력 (Post-Training) — RPE·투구수·운동 체크리스트
  - 선수 정보 수정 / 전체 데이터 초기화 / 알림 / 확인 (시스템 모달 4종)

#### 5-B. 문서/가이드 페이지 7개 (`site/*.html`, 공통 `docs.css`)
모두 같은 마스터 레이아웃(`.doc-wrap`)을 공유하며, 단일 컬럼·중앙 정렬·뒤로가기 링크·하단 메타(최종 수정일 등)가 공통 구조. 각 페이지의 목적과 핵심 섹션:

1. **`about.html` — 서비스 소개**: Baseball Lab S&C란 / 주요 기능 / 사용 대상 / 안전 고지.
2. **`assessment-guide.html` — 8종목 정밀평가 활용법**: 평가 목적 / 점수와 7일 스케줄의 관계 / 점수 해석의 한계 / 재평가 주기.
3. **`recovery-guide.html` — 등판 후 회복 기록 가이드**: 회복 기록의 의미 / 기록 4항목(통증·피로·수면·컨디션) / 통증 발생 시 행동 원칙.
4. **`workload-guide.html` — 워크로드와 ACWR 이해하기**: 워크로드 정의 / ACWR 계산 / 해석상 한계 / 코치·선수·보호자 공동 검토 필요성.
5. **`contact.html` — 문의/지원**: 문의 전 확인사항 / 응대 가능한 항목 / 운영자 연락처.
6. **`privacy.html` — 개인정보처리방침**: 저장 위치(localStorage) / 수집 항목 / 외부 전송 부재 / 백업 파일 보관 책임.
7. **`terms.html` — 이용약관 및 안전 고지**: 앱의 목적 / 안전 주의사항 / 지표의 성격 / 미성년자 데이터 입력 / 면책 범위.

문서 페이지의 디자인 요건:
- 본문 가독성 최우선 (16px 본문, 1.7 line-height 정도).
- 단일 컬럼, max-width 640~720px 정도.
- 메인 앱과 같은 헤더/푸터 또는 최소한 같은 브랜드 마크·컬러 시스템.
- "← 돌아가기" 같은 메인 앱 복귀 링크 명확.
- 본문 안 H2/H3 위계, 인용/노트 박스, 경고 박스(통증·의료 상담 권고 등), 리스트, 표(가능 시) 컴포넌트 지정.
- 약관/개인정보 페이지에서도 시각 톤이 너무 사무적이지 않게 유지.

### 6. 시각·기술 제약
- **언어/타이포**: 한국어 우선. 본문은 Pretendard(가능하면 유지) 또는 동급의 한글 가독성 좋은 산세리프. 라틴 폰트와의 자연스러운 혼용이 중요.
- **자간/행간**: 한글 가독성 우선. 너무 좁거나 너무 넓은 자간 회피.
- **모바일 우선**: 한 손 조작 가능한 터치 타깃, 폼 입력 빈도가 높으므로 입력 UI가 답답하지 않아야 함.
- **다크모드**: 필수는 아니지만 토큰 시스템으로 확장 여지가 있으면 좋음.
- **차트**: Chart.js로 ACWR 라인/막대, 회복 점수 변화 그래프 표시. 시각적 시그널(녹/황/적)이 명확하되 의료적 위협 느낌은 피함.
- **아이콘**: lucide-icons 사용 중. 동등하거나 더 좋은 한 가지 아이콘 시스템을 권장 가능.

### 7. 컬러 가이드 (현재 → 자유 제안)
현재 사이트는 Forest Green (#2d6a4f) + 차콜 오프화이트 배경 (#f4f5f2). 야구 잔디·그라운드를 떠올리는 의도는 유지해도 좋고, 더 나은 브랜드 컬러를 자유롭게 제안해도 됩니다. 단:
- 의료적 강조색(빨강)은 "주의/초과" 신호로만 사용.
- 데이터 시그널 3단계(정상/주의/초과)를 표현할 수 있는 팔레트가 필요.
- 코치용 화면과 선수용 화면이 시각적으로 구별되면 좋음 (강요는 아님).

### 8. 디자인 시스템 산출물
각 방향마다 **메인 앱과 문서 페이지가 같은 토큰을 공유**하도록 제공:
- 공통 컬러 토큰 (primary / secondary / surface 3단계 / 시그널 3단계 / 텍스트 4단계 / border / 차트 4~6색).
- 공통 타이포 스케일 (히어로 H1 / 페이지 H1 / 카드 H2 / 섹션 H3 / 본문 / 캡션 / 모노).
- 공통 라운드·그림자·간격 토큰 (spacing scale: 4/8/12/16/20/24/32/48).
- 공통 컴포넌트: 버튼 3종(primary/secondary/ghost), 입력, 토글, 카드, 모달, 배지·태그, 차트 카드, 인용·노트 박스, 경고 박스, 본문 표·리스트.
- 문서 페이지 전용 추가 토큰: max-width(640~720), 본문 폰트 사이즈, 단락 간격, "돌아가기" 링크 스타일.
- 다크모드 확장 토큰(가능하면).
- 두 컨텍스트가 어떤 점에서 일관되고 어떤 점에서 다른지 1장으로 설명 (예: 문서 페이지는 카드 그림자가 더 약하고, 모달 컴포넌트는 사용하지 않는다 — 같은 식).

### 9. 3가지 방향 제안 가이드
다음 3가지 방향성을 출발점으로 합니다. 더 좋은 방향이 있으면 대체 제안하셔도 됩니다.

1. **"Field & Data"** — 야구장 그라운드를 떠올리는 그린·차콜 베이스 위에 데이터·차트가 또렷이 살아나는 톤. 안정감과 신뢰가 핵심.
2. **"Clinical Trust"** — 화이트·딥 네이비·세이지 기반의 차분한 임상 프리미엄 톤. 여백이 넓고 그림자가 부드러움. 단, 의료기기 분위기까지는 가지 않음.
3. **"Coaching Studio"** — 코치와 선수가 함께 보는 작업실 느낌. 따뜻한 중성톤 + 한 가지 강한 액센트 컬러. 정보 밀도는 높되 부담 없게.

### 10. 출력 요청
- 각 방향마다 데스크톱·모바일 두 사이즈로 섹션 5-A·5-B 화면 모두 보여주기 (메인 앱 8개 + 문서 페이지 마스터 1개 + 문서 페이지 샘플 2개).
- 한국어 더미 텍스트는 본 브리프에 있는 실제 라벨/메시지를 사용 (영문 lorem 사용 금지). 문서 페이지의 경우 각 페이지 첫 H2 이름까지는 본 브리프 5-B의 것을 그대로 쓰고, 본문은 적당한 한국어 더미면 됨.
- 첫 시안 후 사용자 피드백을 받아 한 방향으로 좁히고, 그 방향의 디자인 토큰을 완성된 디자인 시스템으로 export 할 수 있도록 정리.
- Claude Code 핸드오프를 염두에 두고, CSS 변수명과 컴포넌트 클래스명을 함께 제안 (예: `--primary`, `.btn-primary`, `.card`, `.player-row`, `.doc-wrap`, `.doc-back`, `.doc-meta`, `.callout`, `.callout-warn` 등). 현재 사이트에서 이미 쓰는 클래스명(`.card`, `.form-control`, `.modal-title`, `.doc-wrap` 등)은 가능하면 그대로 유지해 마이그레이션 비용을 낮춰 주세요.

### 11. 하지 말 것
- 야구공·배트·홈플레이트 클립아트성 그래픽 남용 금지.
- 어두운 빨강을 브랜드 메인으로 사용 금지 (의료적 경고와 혼동).
- 영어 헤드라인만으로 구성하지 말 것 (한국어 사용자 대상).
- "Optimize", "Predict", "Diagnose", "Prevent", "Boost", "최적", "예측", "진단", "예방" 같은 단어를 카피에 사용 금지.
- 의료 십자가, 청진기, 약병, 처방전 모티프 사용 금지.

질문이 있으면 시안 제시 전에 먼저 물어봐도 됩니다.

- Claude Design 안에서 "**웹 캡처**" 기능으로 현재 사이트 `site/index.html`을 먼저 가져오면, 위 브리프의 "정보 구조"가 실제 화면 컴포넌트와 매핑되어 결과가 더 정확해진다.
- 1차 시안을 받은 뒤 "Field & Data 방향으로 좁히고, 카드 라운드를 줄여 더 데이터 도구 같은 인상을 더해줘" 같은 식으로 좁혀가며 대화한다.
- 최종 시안 확정 후 Claude Design에서 디자인 토큰과 컴포넌트를 export 받아 이쪽 Claude Code 세션에 전달하면, 실제 `site/style.css` 토큰 교체용 코드 티켓을 만들 수 있다.
