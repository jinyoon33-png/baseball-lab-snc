# 홈 랜딩 제품 대시보드 히어로 디자인 스펙

## 목적

루트 홈을 더 세련된 상업 서비스처럼 보이게 만들되, 시작 페이지를 긴 설명문으로 만들지 않는다. 선택한 방향은 C안 `제품 대시보드 히어로형`이다. 목표는 `앱 시작`, `공개 가이드 진입`, `신뢰 신호 요약`을 한 화면 안에서 명확히 보여주는 것이다.

## 디자인 원칙

- 홈은 콘텐츠 문서가 아니라 제품 랜딩이다. 긴 설명은 `/guides`와 개별 가이드 페이지로 보낸다.
- 첫 화면은 짧은 문장, 명확한 CTA, 실제 앱 사용 흐름을 보여주는 미리보기 카드로 구성한다.
- 기존 앱의 Clinical Trust 톤을 유지한다. 새 브랜드 색, 새 폰트, 외부 이미지, 외부 JS는 추가하지 않는다.
- 참고 레퍼런스는 원칙만 사용한다. 토스, Linear, Supabase, TrainingPeaks, WHOOP 이름·문구·레이아웃을 코드나 사용자 노출 문구에 직접 넣지 않는다.
- AdSense 재검토 관점의 신뢰 신호는 남긴다. 홈에 `무엇을 기록하는지`, `공개 가이드가 있다는 점`, `데이터가 브라우저에 저장된다는 점`, `의료 판단을 대신하지 않는다는 점`이 보여야 한다.

## 히어로 구조

히어로는 `텍스트 영역 + 제품 미리보기 패널`의 2열 구조를 유지한다.

- 텍스트 영역: 짧은 kicker, 한 줄에 가까운 강한 headline, 1문장 lead, CTA 2개.
- CTA: `앱 시작하기`는 `/app`, `가이드 보기`는 `/guides`.
- proof row: 회원가입 없음, 브라우저 저장, 기록·평가·스케줄 같은 짧은 신뢰 신호.
- 미리보기 패널: 실제 앱 기능을 떠올릴 수 있는 작은 대시보드 카드로 구성한다. 예: 오늘 입력 완료, 워크로드 RPE·투구 수, 7일 스케줄, ACWR 확인, 8종목 평가.

## 미리보기 패널

미리보기 패널은 현재보다 더 제품 화면처럼 보여야 한다.

- 어두운 네이비 계열 배경을 유지한다.
- 다크모드에서도 배경이 밝게 반전되지 않아야 한다.
- `--hero-gradient-*`, `--hero-text-on-dark`, `--hero-pill-text`, `--hero-glass-*`처럼 히어로 고정 영역 전용 토큰을 우선 사용한다.
- `--ink`, `--surface`처럼 다크모드에서 반전되는 토큰을 히어로 고정 배경/텍스트에 직접 쓰지 않는다.
- 패널 내부 카드는 3~5개로 제한한다. 많아지면 앱 대시보드 느낌이 아니라 표처럼 보인다.

## 하단 섹션 구조

홈 하단은 늘리지 않고 정리한다.

- `기록 / 확인 / 조정` 3개 핵심 가치 섹션은 유지한다.
- 기능 목록은 4개 이내로 유지한다.
- 공개 가이드 카드는 6개 유지하되, 데스크톱에서는 3열 또는 균형 잡힌 2열, 모바일에서는 1열로 표시한다.
- 문장은 자연스럽고 짧게 쓴다. AI가 쓴 듯한 과장형 표현은 피한다.

## 반응형 조건

- 데스크톱 1280px 이상: 히어로 2열, 미리보기 패널 표시, 가이드 3열 가능.
- 태블릿 폭: 히어로가 자연스럽게 1열로 접히거나 미리보기 패널이 아래로 내려간다.
- 모바일 390px: 가로 overflow 0, 히어로 문장 줄바꿈 자연스러움, CTA가 눌리기 쉬운 크기, 가이드 1열. 미리보기 패널은 너무 길어지면 숨기거나 축약한다.
- 라이트/다크모드 모두 대비가 유지되어야 한다.

## 금지 사항

- `site/app.html`, `site/app.js`, `site/data.js`, 저장 schema, 백업/복원 schema 변경 금지.
- `site/guides.html`, `site/about.html`, `site/tokens.css`, `site/docs.css`, `site/sitemap.xml`, `site/robots.txt`, `site/ads.txt` 변경 금지.
- 외부 이미지·폰트·스크립트 추가 금지.
- 광고 스크립트 제거 금지. `index.html`의 AdSense script는 유지한다.
- `index.html`에서 `app.js`, `data.js`, vendor script 로드 금지.
- `치료`, `처방`, `진단`, `보장`, `최적`, `부상 예방`, `성과 향상`, `부상 예측`, `위험 판정`, `자동 추천` 같은 표현을 긍정·단정 문맥으로 추가하지 않는다.

## 검증 기준

- `node --check site/app.js` PASS.
- `node --check site/data.js` PASS.
- inline handler 0건.
- 레퍼런스 사이트명 문자열 0건.
- `site/index.html`에서 앱/vendor script 로드 0건.
- 수정 금지 경로 diff 0건.
- 데스크톱, 모바일 390px, 다크모드 브라우저 확인에서 overflow와 대비 문제가 없어야 한다.
