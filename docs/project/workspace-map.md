# Baseball Lab S&C 작업 공간 맵

## 1. 목적
- 코드 작업, 근거 조사, 보안/QA, 브라우저 실사용 확인, 릴리즈 점검을 파일 범위와 역할 기준으로 분리한다.
- 총괄 Codex는 티켓 선정, 작업 지시, 워크플랜 작성, 최종 검토, 사용자 보고를 담당한다.
- 코드/보안/브라우저/근거/릴리즈 작업은 필요한 티켓마다 하위 에이전트를 생성해 수행한다.
- 하위 에이전트는 작업자이며, 다음 티켓 선정이나 최종 완료 판단을 하지 않는다.
- 전체 문서 분류표는 `docs/README.md`를 기준으로 확인한다.
- 담당별 프롬프트 템플릿은 `docs/project/role-prompts.md`를 기준으로 사용한다.

## 1-1. 업무별 허브
- 코드 작업/워크플랜: `docs/workflow/README.md`
- 근거 조사/검토: `docs/evidence/README.md`
- 보안/QA 점검: `docs/security/README.md`
- 프로젝트 운영 기준: `docs/project/README.md`

## 2. 총괄 Codex 책임
- `docs/workflow/work-plan.md`를 읽고 현재 티켓 또는 다음 티켓을 결정한다.
- 작업에 필요한 하위 에이전트 역할, 허용 파일, 금지 파일, 검증 명령, 보고 형식을 지정한다.
- 하위 에이전트 결과를 그대로 승인하지 않고 `git diff`, 핵심 명령, 브라우저 확인 등으로 직접 대조한다.
- 이슈가 있으면 수정 티켓을 작성하고, 이슈가 없으면 다음 티켓 또는 커밋 여부를 판단한다.
- 사용자에게 현재 담당, 진행 상태, 남은 게이트를 명확히 보고한다.

## 3. 코드 작업 공간
- 현재 티켓: `docs/workflow/work-plan.md`
- 지난 기록: `docs/workflow/work-plan-archive.md`
- 업무 허브: `docs/workflow/README.md`
- 담당 방식:
  - 기본: 총괄 Codex가 티켓을 작성하고 코드 구현 에이전트(worker)를 호출한다.
  - 작은 문서/운영 변경은 총괄 Codex가 직접 수행할 수 있다.
  - 고위험 코드 변경은 구현 후 보안/QA 에이전트 또는 총괄 직접 검토를 거친다.
- 원칙:
  - 코드 티켓은 활성 티켓에 명시된 허용 파일만 수정한다.
  - 구현 에이전트는 다음 티켓을 임의로 선택하지 않는다.
  - 구현 에이전트는 자체 검토 결과를 최종 결론으로 확정하지 않는다.
  - 총괄 Codex가 직접 검증한 뒤 이슈가 있으면 수정 티켓, 없으면 다음 게이트로 넘긴다.
  - 근거 조사 내용은 코드 티켓에 직접 붙이지 않고, 앱 반영은 별도 티켓으로만 진행한다.
  - 권한 차단, 파일 접근 실패, 예상 밖 diff는 우회하지 않고 중단 보고한다.

## 4. 근거 조사 공간
- 현재 근거 작업: `docs/evidence/evidence-research.md`
- 지난 근거 기록: `docs/evidence/evidence-archive.md`
- 업무 허브: `docs/evidence/README.md`
- 담당 방식:
  - 총괄 Codex가 주제를 지정하면 근거/문서 에이전트가 조사한다.
  - 총괄 Codex 또는 근거 검토 에이전트가 출처 신뢰도, 표현 위험, 앱 반영 가능성을 검토한다.
  - 최종 코드 반영 여부는 총괄 Codex가 결정한다.
- 원칙:
  - 근거문서는 구현 지시서가 아니다.
  - 앱 반영은 별도 `docs/workflow/work-plan.md` 티켓으로만 진행한다.
  - 출처가 약한 자료는 보조 근거 또는 보류로 분류한다.
  - 총괄 Codex 판단 질문은 최대 3개로 압축한다.

## 5. 보안/QA 점검 공간
- 업무 허브: `docs/security/README.md`
- 담당 방식:
  - 총괄 Codex가 보안/QA 에이전트에게 읽기 전용 점검을 지시한다.
  - 보안/QA 에이전트는 파일을 수정하지 않고 명령 실행과 보고만 수행한다.
- 허용:
  - 읽기
  - 정적 명령 실행
  - 보안/QA 보고 작성
- 금지:
  - 파일 수정
  - 삭제/이동
  - 커밋
  - 설치
  - 서버 설정 변경
- 호출 기준:
  - CSP, 보안 헤더, localStorage/백업 복원, 외부 링크, 라이선스, 개인정보, XSS/HTML 삽입 경로 변경 시 사용한다.
  - AdSense, analytics, 외부 script, iframe, 광고 위치, privacy/terms 정합성이 바뀔 때 사용한다.
  - 단순 CSS, 문구, QA 기록만 바꾸는 티켓에서는 기본적으로 호출하지 않는다.
  - 보안/QA 보고는 총괄 Codex 판단 자료이며, 그 자체로 최종 결론이 아니다.

## 6. 브라우저 실사용 확인 공간
- 담당 방식:
  - 총괄 Codex가 직접 확인하거나 브라우저 QA 에이전트에게 위임한다.
  - 실사용 확인 전에는 항상 최신 cache bust URL로 인앱 브라우저를 갱신한다.
- 기본 순서:
  - 활성 티켓 확인
  - 사전 정적 확인
  - 브라우저 최신화
  - 데스크톱/태블릿/모바일 확인
  - console error, overflow, 다크모드, 주요 CTA 확인
  - 사용자 회신 기록

## 7. 릴리즈/배포 점검 공간
- 담당 방식:
  - 총괄 Codex가 릴리즈 점검 에이전트에게 커밋 전후 체크를 맡길 수 있다.
  - 최종 커밋·push 판단은 총괄 Codex와 사용자 확인을 따른다.
- 점검 항목:
  - `git status`, `git diff --check`, 변경 파일 범위
  - 실제 도메인 200 OK
  - `ads.txt`, `robots.txt`, `sitemap.xml`, canonical, JSON-LD
  - Cloudflare 배포 후 cache/redirect/HTTPS 상태

## 8. 모델 선택 기준
- `gpt-5.4-mini`: 반복 grep, 파일 목록화, 단순 문서 정리, 간단한 브라우저 체크.
- `gpt-5.4`: 범위가 명확한 HTML/CSS/JS 구현, 일반 QA, 문서 보정.
- 현재 총괄 Codex 또는 높은 모델: 티켓 선정, 출시/보안/AdSense 판단, 저장 schema 변경, 아키텍처 결정, 최종 검토.
- 모델은 작업 난이도에 맞춰 선택하며, 불필요하게 높은 모델을 반복 작업에 쓰지 않는다.

## 9. 최종 판단 흐름
- 총괄 Codex가 현재 티켓과 후속 큐를 확인한다.
- 필요한 경우 코드/근거/브라우저/보안/릴리즈 에이전트를 생성해 작업을 맡긴다.
- 총괄 Codex가 결과를 직접 대조한다.
- 보안 영향이 있으면 보안/QA 에이전트 점검을 거친다.
- 이슈가 있으면 수정 티켓을 작성한다.
- 이슈가 없으면 사용자 확인, 커밋, 다음 티켓 중 무엇이 다음 게이트인지 보고한다.

## 10. 금지
- 하위 에이전트가 다음 티켓을 임의로 선택하지 않는다.
- 하위 에이전트가 최종 완료 판단을 하지 않는다.
- 보안/QA 에이전트는 파일을 수정하지 않는다.
- 근거/문서 에이전트는 `site/*`를 수정하지 않는다.
- 브라우저 QA 에이전트는 파일을 수정하지 않는다.
- 총괄 Codex는 사용자 지시 또는 활성 티켓 없이 `site/*` 코드를 수정하지 않는다.
- 어떤 담당도 사용자 변경사항이나 다른 에이전트 변경사항을 임의로 되돌리지 않는다.
