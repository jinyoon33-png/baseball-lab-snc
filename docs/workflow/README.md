# 코드 작업/워크플랜 공간

## 담당
- 총괄 Codex: 최종 책임자. 티켓 선정, 작업 지시, 워크플랜 작성, 최종 검토, 사용자 보고를 담당한다.
- 코드 구현 에이전트: 총괄 Codex가 지정한 활성 티켓의 허용 파일만 수정한다.
- 보안/QA 에이전트: 보안 영향이 있는 경우 별도 읽기 전용 점검을 수행한다.
- 브라우저 QA 에이전트: 실사용 확인이 필요한 경우 로컬/배포 URL에서 반응형·콘솔·주요 흐름을 확인한다.
- 릴리즈 점검 에이전트: 커밋/배포 전후 상태를 읽기 전용으로 확인한다.

## 작업 규칙
- 모든 코드 구현은 `docs/workflow/work-plan.md`의 활성 티켓 기준으로만 수행한다.
- 총괄 Codex는 작업 시작 전 이번 작업 담당을 사용자에게 알린다.
- 코드 구현 에이전트는 활성 티켓의 수정 허용 파일만 변경한다.
- 보안/QA, 브라우저 QA, 릴리즈 점검 에이전트는 파일을 수정하지 않는다.
- 하위 에이전트는 다음 티켓을 임의로 선택하지 않는다.
- 하위 에이전트는 자체 검토 결론을 최종 완료로 확정하지 않는다.
- 총괄 Codex는 검토 통과 시 후속 큐 기준으로 다음 티켓 또는 다음 게이트를 결정한다.
- 근거 조사 내용은 코드 티켓 본문에 직접 붙이지 않는다. 앱 반영은 총괄 Codex가 별도 티켓으로 전환할 때만 진행한다.
- 권한 차단이나 파일 접근 실패가 발생하면 우회하지 않고 중단 보고한다.
- 보안 영향이 있는 티켓은 총괄 Codex가 보안/QA 에이전트 호출 여부를 결정한다.
- 실사용 확인이 필요한 티켓은 총괄 Codex가 최신 cache bust URL로 브라우저를 갱신한 뒤 확인 항목을 제시한다.

- 변경 요약

- 잔여 리스크
- 총괄 판단 필요 여부

## 에이전트 위임 기준
- 단순 반복 검증, 파일 목록화, 문서 inventory: 낮은 모델 에이전트 사용.
- 범위가 명확한 HTML/CSS/JS 구현: 코드 구현 에이전트 사용.
- XSS, 저장 schema, CSP, 외부 script, AdSense, 개인정보 영향: 보안/QA 에이전트 사용.
- 모바일/데스크톱 실제 UI 확인: 브라우저 QA 에이전트 사용.
- 커밋/배포/도메인/정책 파일 확인: 릴리즈 점검 에이전트 사용.

담당별 전체 시작 프롬프트는 `docs/project/role-prompts.md`를 사용한다.
